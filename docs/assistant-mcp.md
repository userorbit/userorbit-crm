# MCP integration contract

Export `handleMcpRequest(request, env, helpers)` from `src/assistant/mcp.js`; invoke before normal API authentication. It returns null outside its exact routes. Requires DB migration 0053.

Public routes: `/mcp` (POST JSON RPC, GET/DELETE 405), `/.well-known/oauth-protected-resource` and `/.well-known/oauth-protected-resource/mcp`, `/.well-known/oauth-authorization-server`, `/oauth/register`, `/oauth/authorize` (GET consent page, POST authenticated approval), `/oauth/token`, `/oauth/revoke`. Authenticated UI approval route: `/api/assistant/mcp/approvals` (POST).

Helpers: existing `requireAuth(request,env)`, `resolveWorkspaceId(env,request,auth)`, `requireWorkspaceRole(env,userId,workspaceId,roles)`, `requireWorkspaceWrite(env,auth,workspaceId)`. Required dispatcher: **`dispatchAssistantTool(env, workspaceId, name, args, auth)`**. Implement these tool names: `crm_search` ({query,limit?}; query ≤500 chars, limit 1–20), `crm_contact` ({contactId}), `crm_account` ({accountId}), `assistant_search` ({query,limit?}; query ≤500 chars, limit 1–20), `assistant_brief` ({contactId}), `assistant_next_actions` ({}), `assistant_prepare_draft` ({contactId,instructions}). All must scope records to supplied workspace and user; only last tool may mutate and only by creating a draft. No send tool.

For UI approval POST `{tool:"assistant_prepare_draft",arguments:{contactId,instructions}}` using a **user session**, `Authorization: Bearer ...`, `X-Workspace-Id`. Returns `{approval_id,expires_in:300}`. MCP call supplies same arguments plus `approval_id`; approval binds exact canonical arguments, user, workspace and tool and is single use. UI must display exact arguments before requesting approval. Do not expose approval creation as an MCP tool. Coordinator owns UI rendering of draft preview/confirmation.

OAuth consent uses the existing same-origin `crmApiToken` localStorage session, submitted only in an Authorization header. Missing login links to `/app`; user returns to original consent URL after login. A workspace ID is explicitly selected in consent; backend verifies membership. Only session auth can grant OAuth or approve writes. Registered clients are public (`token_endpoint_auth_method:none`), HTTPS redirects or literal loopback HTTP only, exact match, no credentials/fragments. Scopes: `crm:read` and optional `assistant:draft`. Resource is exact origin + `/mcp`. `MCP_PUBLIC_ORIGIN` can pin canonical public origin; `MCP_ALLOWED_ORIGINS` is optional comma-separated browser origins for MCP/OAuth token CORS. Default same-origin. Never include bearer tokens in URLs.

Stateless Streamable HTTP JSON responses, MCP version `2025-06-18` (also accepts `2025-03-26`); only tools capability, no SSE, sessions, resource subscriptions, prompts, sampling, logging or automatic sends. Access tokens expire in 10 minutes, rotating refresh tokens in 7 days (absolute grant lifetime 30 days), codes in 2 minutes. Refresh reuse revokes whole grant. Revoking any access/refresh token revokes grant. Workspace API tokens remain accepted but are bound to their own workspace; writes also need a separate same-user human approval.

Migration tables: `assistant_mcp_clients` (public-client metadata plus hashed registration source), `assistant_mcp_grants` (user/workspace/client/resource/scopes/absolute expiry/revocation), `assistant_mcp_codes` (hashed single-use code and PKCE binding), `assistant_mcp_tokens` (hashed access and refresh tokens), `assistant_mcp_approvals` (exact argument digest, owner, expiry and consumption). Tokens and codes are never stored plaintext. Replaying a valid code also revokes its grant. Registration is limited to 30 clients/hour per hashed Cloudflare connecting IP, or shared unattributed bucket for local/non-Cloudflare requests. Configure edge rate limits for broader abuse control; no remote configuration is applied here.

Request bodies are limited to 64 KiB while reading. Validation rejects unsupported arguments, resource audience mismatches, origins, credentials in query strings, inactive users and workspace overrides. Current membership is checked on every MCP request. Tool execution failures return MCP `isError`; dispatcher internal errors are redacted. Consumed write approvals are not retried on dispatcher failure: review in CRM and approve again. OAuth browser integration is implemented but has not been tested with external MCP clients or deployed credentials. The coordinator must wire the dispatcher and UI; no other feature module is imported.

Protocol references: https://modelcontextprotocol.io/specification/2025-06-18/basic/transports and https://modelcontextprotocol.io/specification/2025-06-18/basic/authorization .

Verification: `bun test tests/mcp.test.js` uses disposable SQLite with actual migrations, including token replay/revocation, scopes, tenant isolation, approval boundaries and protocol validation.
